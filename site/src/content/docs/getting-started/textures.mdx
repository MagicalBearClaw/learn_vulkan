## Three objects, not one

This is the framing worth carrying forward.

```
   VkImage            VkImageView              VkSampler
   the pixels         how to read them         how to read BETWEEN them
   ───────────        ────────────────         ────────────────────────
   format             which mip levels         filtering (linear/nearest)
   size               which array layers       mip selection
   mip count          which format             wrapping past 0..1
   a LAYOUT                                    anisotropy
```

OpenGL merged all three into one texture object, which is why its sampler state was stuck to the
texture and why using the same image with two different filters meant two copies of it. In Vulkan
a sampler is an independent object, and a handful of them typically serve an entire scene.

`stb_image` is header-only, so exactly one translation unit has to compile its implementation.
**`STB_IMAGE_STATIC` is not optional here**: from chapter 3.1 onward Assimp is linked in, and its
static library exports all 43 `stbi_*` symbols itself. A second global definition makes every Part
3 target fail to link with `multiple definition of stbi_load`. Keeping this copy internal to the
file avoids that permanently.

`<bit>` is for `std::bit_width`, which computes the mip count below.

## Getting pixels in


```cpp title="code/src/1.getting_started/textures/main.cpp"
    void load_texture(const std::filesystem::path& path) {
        int width = 0;
        int height = 0;
        int channels = 0;

        stbi_uc* pixels =
            stbi_load(path.string().c_str(), &width, &height, &channels, STBI_rgb_alpha);
        if (pixels == nullptr) {
            throw std::runtime_error(std::format(
                "Could not load '{}': {}. Did you run tools/make_textures.py?",
                path.string(), stbi_failure_reason()));
        }

        const VkDeviceSize size =
            static_cast<VkDeviceSize>(width) * static_cast<VkDeviceSize>(height) * 4;
```

`STBI_rgb_alpha` forces 4 channels whatever the file has. Three-channel *image* formats are
patchily supported across hardware — unlike three-channel vertex formats, which are universal —
and one wasted byte per texel is a far better trade than a support matrix. `channels` still
reports what the file actually had, which is why it is logged below.

The casts before the multiply matter: `width * height * 4` in `int` overflows at about 23 000
pixels square, and the result would be silently negative.

```cpp title="code/src/1.getting_started/textures/main.cpp"
        mip_levels_ = static_cast<uint32_t>(std::bit_width(static_cast<uint32_t>(
                          std::max(width, height))));

        spdlog::info("Loaded {}x{} texture ({} channels in the file), {} mip levels",
                     width, height, channels, mip_levels_);
```

How many times the image can be halved before it reaches 1×1, inclusive. `bit_width(512)` is 10,
and a 512×512 texture has exactly 10 levels: 512, 256, 128 … 2, 1.

```cpp title="code/src/1.getting_started/textures/main.cpp"
        vkc::Buffer staging(context().allocator(), size,
                            VK_BUFFER_USAGE_TRANSFER_SRC_BIT,
                            VMA_ALLOCATION_CREATE_HOST_ACCESS_SEQUENTIAL_WRITE_BIT |
                                VMA_ALLOCATION_CREATE_MAPPED_BIT);
        std::memcpy(staging.mapped(), pixels, static_cast<size_t>(size));
        stbi_image_free(pixels);

        create_image(static_cast<uint32_t>(width), static_cast<uint32_t>(height));
```

Exactly chapter 1.8's staging pattern. The stb allocation is freed as soon as the bytes are in the
staging buffer.

## The image

```cpp title="code/src/1.getting_started/textures/main.cpp"
    void create_image(uint32_t width, uint32_t height) {
        const VkImageCreateInfo image_info{
            .sType = VK_STRUCTURE_TYPE_IMAGE_CREATE_INFO,
            .pNext = nullptr,
            .flags = 0,
            .imageType = VK_IMAGE_TYPE_2D,
            .format = VK_FORMAT_R8G8B8A8_SRGB,
            .extent = {width, height, 1},
            .mipLevels = mip_levels_,
            .arrayLayers = 1,
            .samples = VK_SAMPLE_COUNT_1_BIT,
            .tiling = VK_IMAGE_TILING_OPTIMAL,
            .usage = VK_IMAGE_USAGE_TRANSFER_SRC_BIT | VK_IMAGE_USAGE_TRANSFER_DST_BIT |
                     VK_IMAGE_USAGE_SAMPLED_BIT,
            .sharingMode = VK_SHARING_MODE_EXCLUSIVE,
            .queueFamilyIndexCount = 0,
            .pQueueFamilyIndices = nullptr,
            .initialLayout = VK_IMAGE_LAYOUT_UNDEFINED,
        };
```

Four fields deserve a note.

**`VK_IMAGE_TILING_OPTIMAL`** lets the driver store the texels in whatever order its texture units
prefer — usually some tiled or Morton ordering, never plain rows:

```
   LINEAR                          OPTIMAL (one possible scheme)
   row 0: 0  1  2  3  4  5         0  1  4  5  16 17 20 21
   row 1: 6  7  8  9  10 11        2  3  6  7  18 19 22 23
                                   neighbouring texels in 2D are
   a 2D neighbourhood is           near each other in memory, so one
   scattered across memory         cache line serves a whole quad
```

That locality is why a texture fetch hits cache. `LINEAR` tiling keeps row order and is
dramatically slower to sample; it exists for images the CPU must read directly.

**`TRANSFER_SRC` as well as `TRANSFER_DST`**, because generating mipmaps reads level *n* to write
level *n+1*. Forget it and mip generation is a validation error.

**`extent`** is three-dimensional even for a 2D image, with depth 1. The same struct describes a
3D texture.

**`initialLayout`** must be `UNDEFINED` or `PREINITIALIZED`. `UNDEFINED` says the contents are not
worth preserving, which is exactly true for a new image and lets the first transition be free.

And `_SRGB` rather than `_UNORM`, which needs its own paragraph.

:::note[Why the format ends in `_SRGB`]
Image files store colour in sRGB: roughly, the square root of brightness, because that spends more
bits where the eye is more sensitive. Adding or multiplying those values directly is meaningless —
half of an sRGB value is not half the light.

An `_SRGB` format makes the hardware convert to linear as each texel is sampled, for free. Our
swapchain is also sRGB (chapter 1.4 chose it deliberately), so the conversion back happens on the
way out, also free. Shading happens in linear space in between, which is the only place it is
correct.

Rule of thumb: **colour** textures are `_SRGB`; **data** textures — normal maps, roughness,
height, masks — are `_UNORM`, because they were never colour and converting them would corrupt
them. Chapter 5.2 takes this apart in full.
:::

## The copy, and the layouts

```cpp title="code/src/1.getting_started/textures/main.cpp"
        vkc::immediate_submit(context(), [&](VkCommandBuffer cmd) {
            transition(cmd, VK_IMAGE_LAYOUT_UNDEFINED,
                       VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL, 0, mip_levels_);

            const VkBufferImageCopy region{
                .bufferOffset = 0,
                .bufferRowLength = 0,
                .bufferImageHeight = 0,
                .imageSubresource =
                    {
                        .aspectMask = VK_IMAGE_ASPECT_COLOR_BIT,
                        .mipLevel = 0,
                        .baseArrayLayer = 0,
                        .layerCount = 1,
                    },
                .imageOffset = {0, 0, 0},
                .imageExtent = {static_cast<uint32_t>(width),
                                static_cast<uint32_t>(height), 1},
            };
            vkCmdCopyBufferToImage(cmd, staging.handle(), texture_,
                                   VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL, 1, &region);

            generate_mipmaps(cmd, width, height);
        });

        context().name(texture_, VK_OBJECT_TYPE_IMAGE, "lvk_grid");

        create_texture_view();
    }
```

`vkCmdCopyBufferToImage` moves bytes from a buffer into an image, and a `VkBufferImageCopy`
describes one such move: where in the buffer to read, which mip level and array layer to
write, and what rectangle of the image to cover. It is the image-shaped counterpart of
chapter 1.8's `VkBufferCopy`, and it needs the extra fields because an image has a shape
where a buffer has only a length.

The layout is the new idea here. Chapter 1.5 met it for swapchain images; this is the same
mechanism, and these are the four layouts that cover most work:

| Layout | For |
|---|---|
| `UNDEFINED` | contents not worth keeping — only ever a source |
| `TRANSFER_DST_OPTIMAL` | being copied into |
| `TRANSFER_SRC_OPTIMAL` | being copied out of |
| `SHADER_READ_ONLY_OPTIMAL` | being sampled |

`bufferRowLength` and `bufferImageHeight` of zero mean "tightly packed", which is what stb gives
us. Non-zero values describe a sub-rectangle of a larger source image.

Note that the copy writes only `mipLevel = 0`. The rest of the chain does not exist yet — the
image has ten levels of allocated memory with nothing in nine of them.

```cpp title="code/src/1.getting_started/textures/main.cpp"
    void transition(VkCommandBuffer cmd, VkImageLayout from, VkImageLayout to,
                    uint32_t base_mip, uint32_t mip_count) {
        const VkImageMemoryBarrier2 barrier{
            .sType = VK_STRUCTURE_TYPE_IMAGE_MEMORY_BARRIER_2,
            .pNext = nullptr,
            .srcStageMask = VK_PIPELINE_STAGE_2_ALL_COMMANDS_BIT,
            .srcAccessMask = VK_ACCESS_2_MEMORY_WRITE_BIT,
            .dstStageMask = VK_PIPELINE_STAGE_2_ALL_COMMANDS_BIT,
            .dstAccessMask = VK_ACCESS_2_MEMORY_WRITE_BIT | VK_ACCESS_2_MEMORY_READ_BIT,
            .oldLayout = from,
            .newLayout = to,
            .srcQueueFamilyIndex = VK_QUEUE_FAMILY_IGNORED,
            .dstQueueFamilyIndex = VK_QUEUE_FAMILY_IGNORED,
            .image = texture_,
            .subresourceRange =
                {
                    .aspectMask = VK_IMAGE_ASPECT_COLOR_BIT,
                    .baseMipLevel = base_mip,
                    .levelCount = mip_count,
                    .baseArrayLayer = 0,
                    .layerCount = 1,
                },
        };

        const VkDependencyInfo dependency{
            .sType = VK_STRUCTURE_TYPE_DEPENDENCY_INFO,
            .pNext = nullptr,
            .dependencyFlags = 0,
            .memoryBarrierCount = 0,
            .pMemoryBarriers = nullptr,
            .bufferMemoryBarrierCount = 0,
            .pBufferMemoryBarriers = nullptr,
            .imageMemoryBarrierCount = 1,
            .pImageMemoryBarriers = &barrier,
        };

        vkCmdPipelineBarrier2(cmd, &dependency);
    }
```

Chapter 1.5's `transition_image` with a **mip range** added. That is the whole difference, and it
is the point of the chapter's middle section: `baseMipLevel` and `levelCount` mean a layout
belongs to a *subresource*, not to an image. Different levels of the same image can be in
different layouts at the same time, and mip generation depends on exactly that.

## Mipmaps

When a texture is minified — many texels falling inside one pixel — sampling picks one of them and
ignores the rest. Move the camera slightly and it picks a different one. The result shimmers, and
it is far more distracting in motion than a still screenshot suggests.

A **mip chain** is the texture pre-filtered at successively half sizes:

```
   level 0   512x512   ████████████████
   level 1   256x256   ████████
   level 2   128x128   ████
   ...                                  total cost: +33% memory
   level 9   1x1       ▪                and FASTER, because small levels fit in cache
```

The hardware picks the level where one texel is about one pixel, so it averages over the right
area instead of point-sampling a random texel.

Vulkan has **no `vkCmdGenerateMipmaps`**. That is deliberate — a box filter is rarely the best
downsample, and production pipelines generate mips offline with something better. At load time,
`vkCmdBlitImage` is the pragmatic answer.

```cpp title="code/src/1.getting_started/textures/main.cpp"
    void generate_mipmaps(VkCommandBuffer cmd, int width, int height) {
        VkFormatProperties properties{};
        vkGetPhysicalDeviceFormatProperties(context().physical_device(),
                                            VK_FORMAT_R8G8B8A8_SRGB, &properties);
        if ((properties.optimalTilingFeatures &
             VK_FORMAT_FEATURE_SAMPLED_IMAGE_FILTER_LINEAR_BIT) == 0) {
            throw std::runtime_error(
                "This GPU cannot linearly filter R8G8B8A8_SRGB blits, so mipmaps "
                "cannot be generated this way.");
        }

        int mip_width = width;
        int mip_height = height;
```

:::caution[Linear blit is an optional feature]
`vkGetPhysicalDeviceFormatProperties` asks the GPU what it can do with one particular
format — sample it, filter it, use it as an attachment, blit it — and returns a set of
feature bits for each kind of tiling.

`VK_FORMAT_FEATURE_SAMPLED_IMAGE_FILTER_LINEAR_BIT` is not guaranteed for every format. For 8-bit
formats it is supported everywhere in practice — but "in practice" is not a guarantee, so it is
checked, in the same "ask, do not assume" spirit as chapter 1.3's device selection.

For compressed formats (BC7, ASTC) blitting is not available at all, and their mips must be
generated offline — which is what you want anyway.
:::

```cpp title="code/src/1.getting_started/textures/main.cpp"
        for (uint32_t level = 1; level < mip_levels_; ++level) {
            transition(cmd, VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL,
                       VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL, level - 1, 1);

            const int next_width = std::max(mip_width / 2, 1);
            const int next_height = std::max(mip_height / 2, 1);

            const VkImageBlit blit{
                .srcSubresource =
                    {
                        .aspectMask = VK_IMAGE_ASPECT_COLOR_BIT,
                        .mipLevel = level - 1,
                        .baseArrayLayer = 0,
                        .layerCount = 1,
                    },
                .srcOffsets = {{0, 0, 0}, {mip_width, mip_height, 1}},
                .dstSubresource =
                    {
                        .aspectMask = VK_IMAGE_ASPECT_COLOR_BIT,
                        .mipLevel = level,
                        .baseArrayLayer = 0,
                        .layerCount = 1,
                    },
                .dstOffsets = {{0, 0, 0}, {next_width, next_height, 1}},
            };

            vkCmdBlitImage(cmd, texture_, VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL, texture_,
                           VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL, 1, &blit,
                           VK_FILTER_LINEAR);

            transition(cmd, VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL,
                       VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL, level - 1, 1);

            mip_width = next_width;
            mip_height = next_height;
        }

        transition(cmd, VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL,
                   VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL, mip_levels_ - 1, 1);
    }
```

A `VkImageBlit` describes the rescaling copy: a source mip level with the rectangle to read
from it, and a destination mip level with the rectangle to write into. The two `Offsets`
arrays each hold two corners, so the source rectangle is the whole of level *n* and the
destination is the whole of level *n+1*, which is half the size — and that size difference
is what makes the blit filter rather than copy.

Read the loop as a ladder, one level at a time:

```
   level 0:  DST ──▶ SRC ──blit──▶ level 1 (DST)
             then 0: SRC ──▶ SHADER_READ_ONLY, finished forever

   level 1:  DST ──▶ SRC ──blit──▶ level 2 (DST)
             then 1: SRC ──▶ SHADER_READ_ONLY
   ...
   level 9:  never a source, so it is still DST after the loop
             ──▶ one final transition
```

That last asymmetry is the easiest thing to get wrong here, and the symptom is a validation error
naming exactly one mip level.

Notice the same image is both source and destination of the blit, at different mip levels. That is
legal precisely because the levels are in different layouts and the barriers order them.

`std::max(mip_width / 2, 1)` is not decoration either: a non-square texture reaches 1 in one axis
before the other, and halving 1 gives 0, which is not a legal extent.

## The view

```cpp title="code/src/1.getting_started/textures/main.cpp"
    void create_texture_view() {
        const VkImageViewCreateInfo view_info{
            .sType = VK_STRUCTURE_TYPE_IMAGE_VIEW_CREATE_INFO,
            .pNext = nullptr,
            .flags = 0,
            .image = texture_,
            .viewType = VK_IMAGE_VIEW_TYPE_2D,

```

The same structure chapter 1.4 used for swapchain images, with `levelCount` now meaning something.
A view exposing a subset of the chain is how you sample one specific level — which is what a bloom
or blur pass does.

## The sampler

```cpp title="code/src/1.getting_started/textures/main.cpp"
    void create_sampler() {
        const float max_anisotropy =
            context().gpu_properties().limits.maxSamplerAnisotropy;

        const VkSamplerCreateInfo sampler_info{
            .sType = VK_STRUCTURE_TYPE_SAMPLER_CREATE_INFO,
            .pNext = nullptr,
            .flags = 0,
            .magFilter = VK_FILTER_LINEAR,
            .minFilter = VK_FILTER_LINEAR,
            .mipmapMode = VK_SAMPLER_MIPMAP_MODE_LINEAR,
            .addressModeU = VK_SAMPLER_ADDRESS_MODE_REPEAT,
            .addressModeV = VK_SAMPLER_ADDRESS_MODE_REPEAT,
            .addressModeW = VK_SAMPLER_ADDRESS_MODE_REPEAT,
            .mipLodBias = 0.0F,
            .anisotropyEnable = VK_TRUE,
            .maxAnisotropy = max_anisotropy,
            .compareEnable = VK_FALSE,
            .compareOp = VK_COMPARE_OP_ALWAYS,
            .minLod = 0.0F,
            .maxLod = VK_LOD_CLAMP_NONE,
            .borderColor = VK_BORDER_COLOR_INT_OPAQUE_BLACK,
            .unnormalizedCoordinates = VK_FALSE,
        };
        VK_CHECK(vkCreateSampler(context().device(), &sampler_info, nullptr, &sampler_));

        spdlog::info("Sampler created with maxAnisotropy={}", max_anisotropy);
    }
```

The sampler is where most of the visible quality decisions live. Note that it names **no image at
all** — that is the point of it being a separate object.

**`magFilter`** is magnification, one texel covering many pixels. **`minFilter`** is minification,
many texels per pixel, which is where aliasing lives:

```
   magnification          minification
   NEAREST: blocky        NEAREST: shimmers as the camera moves
   LINEAR:  smooth        LINEAR + mipmaps: stable
```

**`mipmapMode`** is how to blend *between* two mip levels. `LINEAR` gives trilinear filtering;
`NEAREST` picks one level, and you can see the seam where it switches as a band across a floor.

**`addressMode`** decides what `u` or `v` outside 0…1 means:

| Mode | Behaviour |
|---|---|
| `REPEAT` | tiles — the right-hand quad in the screenshot |
| `MIRRORED_REPEAT` | tiles, flipping alternate copies, so edges always match |
| `CLAMP_TO_EDGE` | stretches the edge texel outwards |
| `CLAMP_TO_BORDER` | uses `borderColor` |

`CLAMP_TO_EDGE` is the right default for anything not meant to tile. `REPEAT` on a non-tiling
texture produces a thin wrong-coloured line at the edges, from the filter blending the left edge
with the right.

**`anisotropyEnable`** is the best value for money in the whole struct. A surface at a glancing
angle is compressed in one direction and not the other, and an ordinary mip lookup has to pick a
level blurry enough for the worse axis. Anisotropic filtering takes several samples along the
stretched direction instead. It needs the `samplerAnisotropy` device feature, which chapter 1.3
enabled — and `maxSamplerAnisotropy` is read from the device rather than hard-coded to 16, because
the limit is not guaranteed.

**`compareEnable`** turns this into a *comparison* sampler, returning a pass/fail fraction rather
than a colour. That is what shadow mapping uses, in chapter 5.3.

**`maxLod = VK_LOD_CLAMP_NONE`** means no limit, which stays correct if a view later exposes a
different number of levels.

## Reaching the shader

```cpp title="code/src/1.getting_started/textures/main.cpp"
    void create_descriptors() {
        const VkDevice device = context().device();

        const VkDescriptorSetLayoutBinding binding{
            .binding = 0,
            .descriptorType = VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER,
            .descriptorCount = 1,
            .stageFlags = VK_SHADER_STAGE_FRAGMENT_BIT,
            .pImmutableSamplers = nullptr,
        };

        const VkDescriptorSetLayoutCreateInfo layout_info{
            .sType = VK_STRUCTURE_TYPE_DESCRIPTOR_SET_LAYOUT_CREATE_INFO,
            .pNext = nullptr,
            .flags = 0,
            .bindingCount = 1,
            .pBindings = &binding,
        };
        VK_CHECK(vkCreateDescriptorSetLayout(device, &layout_info, nullptr,
                                             &set_layout_));

        const VkDescriptorPoolSize pool_size{
            .type = VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER,
            .descriptorCount = 1,
        };

        const VkDescriptorPoolCreateInfo pool_info{
            .sType = VK_STRUCTURE_TYPE_DESCRIPTOR_POOL_CREATE_INFO,
            .pNext = nullptr,
            .flags = 0,
            .maxSets = 1,
            .poolSizeCount = 1,
            .pPoolSizes = &pool_size,
        };
        VK_CHECK(vkCreateDescriptorPool(device, &pool_info, nullptr, &descriptor_pool_));

        const VkDescriptorSetAllocateInfo alloc_info{
            .sType = VK_STRUCTURE_TYPE_DESCRIPTOR_SET_ALLOCATE_INFO,
            .pNext = nullptr,
            .descriptorPool = descriptor_pool_,
            .descriptorSetCount = 1,
            .pSetLayouts = &set_layout_,
        };
        VK_CHECK(vkAllocateDescriptorSets(device, &alloc_info, &descriptor_set_));
```

`COMBINED_IMAGE_SAMPLER` is one descriptor holding both a view and a sampler. Vulkan also offers
`SAMPLED_IMAGE` and `SAMPLER` separately, which is how one image gets paired with several samplers
without duplicating anything — but combined is simpler and is where to start.
`pImmutableSamplers` is a third option: a sampler baked into the *layout*, which the descriptor
then cannot change.

Note there is **one** descriptor set this time, not one per frame in flight. Nothing in it changes:
it points at the same texture and sampler every frame. The per-frame duplication in 1.10 was needed
because the *contents* of that buffer changed.

```cpp title="code/src/1.getting_started/textures/main.cpp"
        const VkDescriptorImageInfo image_info{
            .sampler = sampler_,
            .imageView = texture_view_,
            .imageLayout = VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL,
        };

        const VkWriteDescriptorSet write{
            .sType = VK_STRUCTURE_TYPE_WRITE_DESCRIPTOR_SET,
            .pNext = nullptr,
            .dstSet = descriptor_set_,
            .dstBinding = 0,
            .dstArrayElement = 0,
            .descriptorCount = 1,
            .descriptorType = VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER,
            .pImageInfo = &image_info,
            .pBufferInfo = nullptr,
            .pTexelBufferView = nullptr,
        };
        vkUpdateDescriptorSets(device, 1, &write, 0, nullptr);
    }
```

A `VkDescriptorImageInfo` is the image-shaped descriptor, the counterpart of chapter 1.10's
`VkDescriptorBufferInfo`: a sampler, a view, and the layout the image will be in when it is
read. `pImageInfo` is populated where 1.10 populated `pBufferInfo` — the same
`VkWriteDescriptorSet`, with a different one of its three pointers in use.

The `imageLayout` here is a **promise**, checked by the validation layers at draw time: this is the

:::note[`Sample()` does more than a memory read]
The hardware compares this fragment's `uv` against its neighbours' — which is *why* fragment
shaders run in groups of at least 2×2 — works out how fast the coordinate is changing across the
screen, picks the mip level where one texel is about one pixel, and blends the two nearest levels.
All of that is one instruction.

It also means `Sample()` inside non-uniform control flow is trouble: if some fragments in the group
took the other branch, their `uv` is undefined and so is the derivative. Sample first, branch
afterwards. `SampleLevel()` names the mip level explicitly and is safe anywhere.
:::

```cpp title="code/common/scaffold/src/image.cpp"
void Image::transition(VkCommandBuffer cmd, VkImageLayout from, VkImageLayout to,
                       uint32_t base_mip, uint32_t mip_count) const {
    const VkImageMemoryBarrier2 barrier{
        .sType = VK_STRUCTURE_TYPE_IMAGE_MEMORY_BARRIER_2,
        .pNext = nullptr,
        .srcStageMask = VK_PIPELINE_STAGE_2_ALL_COMMANDS_BIT,
        .srcAccessMask = VK_ACCESS_2_MEMORY_WRITE_BIT,
        .dstStageMask = VK_PIPELINE_STAGE_2_ALL_COMMANDS_BIT,
        .dstAccessMask = VK_ACCESS_2_MEMORY_WRITE_BIT | VK_ACCESS_2_MEMORY_READ_BIT,
        .oldLayout = from,
        .newLayout = to,
        .srcQueueFamilyIndex = VK_QUEUE_FAMILY_IGNORED,
        .dstQueueFamilyIndex = VK_QUEUE_FAMILY_IGNORED,
        .image = image_,
        .subresourceRange =
            {
                .aspectMask = desc_.aspect,
                .baseMipLevel = base_mip,
                .levelCount = mip_count,
                .baseArrayLayer = 0,
                // Every layer. A cubemap transitioned one face at a time would leave
                // the other five in whatever layout they were in, and the mismatch is
                // undefined behaviour rather than a validation error on most paths.
                .layerCount = desc_.array_layers,
            },
    };

    const VkDependencyInfo dependency{
        .sType = VK_STRUCTURE_TYPE_DEPENDENCY_INFO,
        .pNext = nullptr,
        .dependencyFlags = 0,
        .memoryBarrierCount = 0,
        .pMemoryBarriers = nullptr,
        .bufferMemoryBarrierCount = 0,
        .pBufferMemoryBarriers = nullptr,
        .imageMemoryBarrierCount = 1,
        .pImageMemoryBarriers = &barrier,
    };

    vkCmdPipelineBarrier2(cmd, &dependency);
}
```

```cpp title="code/common/scaffold/src/image.cpp"
namespace {

// Chapter 1.11's mip ladder: blit level n-1 into level n, halved, then park level n-1
// in the layout the shader wants.
void generate_mipmaps(VkCommandBuffer cmd, const Image& image) {
    int mip_width = static_cast<int>(image.extent().width);
    int mip_height = static_cast<int>(image.extent().height);

    for (uint32_t level = 1; level < image.mip_levels(); ++level) {
        image.transition(cmd, VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL,
                         VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL, level - 1, 1);

        const int next_width = std::max(mip_width / 2, 1);
        const int next_height = std::max(mip_height / 2, 1);

        const VkImageBlit blit{
            .srcSubresource = {VK_IMAGE_ASPECT_COLOR_BIT, level - 1, 0, 1},
            .srcOffsets = {{0, 0, 0}, {mip_width, mip_height, 1}},
            .dstSubresource = {VK_IMAGE_ASPECT_COLOR_BIT, level, 0, 1},
            .dstOffsets = {{0, 0, 0}, {next_width, next_height, 1}},
        };

        vkCmdBlitImage(cmd, image.handle(), VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL,
                       image.handle(), VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL, 1, &blit,
                       VK_FILTER_LINEAR);

        image.transition(cmd, VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL,
                         VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL, level - 1, 1);

        mip_width = next_width;
        mip_height = next_height;
    }

    image.transition(cmd, VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL,
                     VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL,
                     image.mip_levels() - 1, 1);
}

}  // namespace
```

```cpp title="code/common/scaffold/src/image.cpp"
                    .format = format,
                    .extent = extent,
                    .usage = VK_IMAGE_USAGE_TRANSFER_SRC_BIT |
                             VK_IMAGE_USAGE_TRANSFER_DST_BIT |
                             VK_IMAGE_USAGE_SAMPLED_BIT,
                    .mip_levels = mip_level_count(extent.width, extent.height),
                    .aspect = VK_IMAGE_ASPECT_COLOR_BIT,
                });

    Buffer staging(context.allocator(), size, VK_BUFFER_USAGE_TRANSFER_SRC_BIT,
                   VMA_ALLOCATION_CREATE_HOST_ACCESS_SEQUENTIAL_WRITE_BIT |
                       VMA_ALLOCATION_CREATE_MAPPED_BIT);
    std::memcpy(staging.mapped(), rgba_pixels, static_cast<size_t>(size));

    immediate_submit(context, [&](VkCommandBuffer cmd) {
        image.transition(cmd, VK_IMAGE_LAYOUT_UNDEFINED,
                         VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL);

        const VkBufferImageCopy region{
            .bufferOffset = 0,
            .bufferRowLength = 0,
            .bufferImageHeight = 0,
            .imageSubresource = {VK_IMAGE_ASPECT_COLOR_BIT, 0, 0, 1},
            .imageOffset = {0, 0, 0},
            .imageExtent = {extent.width, extent.height, 1},
        };
        vkCmdCopyBufferToImage(cmd, staging.handle(), image.handle(),
                               VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL, 1, &region);

        generate_mipmaps(cmd, image);
    });

    return image;
}
```

The whole of this chapter's upload path, from the format check to the staging copy to the
mip ladder, in one function. The `staging` buffer is a local, so chapter 1.8's lifetime
lesson applies again: it is destroyed as the function returns, which is after
`immediate_submit` has waited.

```cpp title="code/common/scaffold/src/image.cpp"
Image load_texture(Context& context, const std::filesystem::path& path,
                   VkFormat format) {
    int width = 0;
    int height = 0;
    int channels = 0;
    // The deleter is not decoration: create_texture throws on a GPU that cannot filter
    // this format, and a bare stbi_uc* would leak the decoded image on the way out.
    const std::unique_ptr<stbi_uc, void (*)(void*)> pixels(
        stbi_load(path.string().c_str(), &width, &height, &channels, STBI_rgb_alpha),
        stbi_image_free);
    if (pixels == nullptr) {
        throw std::runtime_error(
            std::format("Could not load '{}': {}. Did you run tools/make_textures.py?",
                        path.string(), stbi_failure_reason()));
    }

    return create_texture(context, pixels.get(),
                          {static_cast<uint32_t>(width), static_cast<uint32_t>(height)},
                          format);
}
```

The one genuine improvement over your version. Yours called `stbi_image_free(pixels)`
explicitly after the memcpy; this wraps the pointer in a `std::unique_ptr` with
`stbi_image_free` as a **custom deleter**, so the allocation is released however the
function exits.

The comment says why that matters: `create_texture` throws on a GPU that cannot filter the
format, and a raw pointer would leak the decoded image on the way out. The
`void (*)(void*)` in the type is the deleter's function-pointer type, which a `unique_ptr`
needs spelled out when the deleter is not the default.

```cpp title="code/common/scaffold/src/image.cpp"
Image load_cubemap(Context& context, const std::array<std::filesystem::path, 6>& faces,
                   VkFormat format) {
    // Decode all six first, so that a missing or mis-sized file is discovered before any
    // GPU memory is committed to it.
    std::array<std::unique_ptr<stbi_uc, void (*)(void*)>, 6> pixels{
        {{nullptr, stbi_image_free},
         {nullptr, stbi_image_free},
         {nullptr, stbi_image_free},
         {nullptr, stbi_image_free},
         {nullptr, stbi_image_free},
         {nullptr, stbi_image_free}}};
    int size = 0;

    for (size_t face = 0; face < faces.size(); ++face) {
        int width = 0;
        int height = 0;
        int channels = 0;
        pixels[face] = {stbi_load(faces[face].string().c_str(), &width, &height,
                                  &channels, STBI_rgb_alpha),
                        stbi_image_free};
        if (pixels[face] == nullptr) {
            throw std::runtime_error(
                std::format("Could not load cubemap face '{}': {}",
                            faces[face].string(), stbi_failure_reason()));
        }
        if (width != height) {
            throw std::runtime_error(std::format(
                "Cubemap face '{}' is {}x{}; every face must be square.",
                faces[face].string(), width, height));
        }
        if (face == 0) {
            size = width;
        } else if (width != size) {
            throw std::runtime_error(std::format(
                "Cubemap face '{}' is {}x{}, but the first face is {}x{}; all six must "
                "match.",
                faces[face].string(), width, height, size, size));
        }
    }
```

This function belongs to chapter 4.4 and is shown here only because it lives in this file.
The one idea worth taking now is the **validate-everything-first** shape: all six faces are
decoded and checked before any GPU memory is committed, so a typo in the fifth filename
fails before five images have been allocated.

```cpp title="code/common/scaffold/src/image.cpp"
    const auto extent_side = static_cast<uint32_t>(size);
    Image image(context, ImageDesc{
                             .format = format,
                             .extent = {extent_side, extent_side},
                             .usage = VK_IMAGE_USAGE_TRANSFER_DST_BIT |
                                      VK_IMAGE_USAGE_SAMPLED_BIT,
                             .mip_levels = 1,
                             .aspect = VK_IMAGE_ASPECT_COLOR_BIT,
                             .array_layers = 6,
                             .cube = true,
                         });

    const VkDeviceSize face_bytes =
        static_cast<VkDeviceSize>(extent_side) * extent_side * 4;

    // One staging buffer holding the six faces back to back: one allocation and one
    // submit rather than six of each.
    Buffer staging(context.allocator(), face_bytes * 6, VK_BUFFER_USAGE_TRANSFER_SRC_BIT,
                   VMA_ALLOCATION_CREATE_HOST_ACCESS_SEQUENTIAL_WRITE_BIT |
                       VMA_ALLOCATION_CREATE_MAPPED_BIT);
    for (size_t face = 0; face < faces.size(); ++face) {
        std::memcpy(static_cast<std::byte*>(staging.mapped()) +
                        static_cast<size_t>(face_bytes) * face,
                    pixels[face].get(), static_cast<size_t>(face_bytes));
    }

    immediate_submit(context, [&](VkCommandBuffer cmd) {
        image.transition(cmd, VK_IMAGE_LAYOUT_UNDEFINED,
                         VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL);

        // One region per face. baseArrayLayer is the only field that differs between
        // them, and it is how the six blocks of the staging buffer find their faces.
        std::array<VkBufferImageCopy, 6> regions{};
        for (uint32_t face = 0; face < 6; ++face) {
            regions[face] = VkBufferImageCopy{
                .bufferOffset = face_bytes * face,
                .bufferRowLength = 0,
                .bufferImageHeight = 0,
                .imageSubresource = {VK_IMAGE_ASPECT_COLOR_BIT, 0, face, 1},
                .imageOffset = {0, 0, 0},
                .imageExtent = {extent_side, extent_side, 1},
            };
        }
        vkCmdCopyBufferToImage(cmd, staging.handle(), image.handle(),
                               VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL,
                               static_cast<uint32_t>(regions.size()), regions.data());

        image.transition(cmd, VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL,
                         VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL);
    });

    return image;
}
```

The six faces go into **one** staging buffer back to back, and one
`vkCmdCopyBufferToImage` with six regions puts each block into its array layer. That is the
`regionCount` argument earning its keep — the same call this chapter made with one region.

```cpp title="code/common/scaffold/src/image.cpp"
Sampler::Sampler(Context& context, const SamplerDesc& desc)
    : device_(context.device()) {
    const VkSamplerCreateInfo info{
        .sType = VK_STRUCTURE_TYPE_SAMPLER_CREATE_INFO,
        .pNext = nullptr,
        .flags = 0,
        .magFilter = desc.mag_filter,
        .minFilter = desc.min_filter,
        .mipmapMode = desc.mipmap_mode,
        .addressModeU = desc.address_mode,
        .addressModeV = desc.address_mode,
        .addressModeW = desc.address_mode,
        .mipLodBias = 0.0F,
        .anisotropyEnable = desc.anisotropy ? VK_TRUE : VK_FALSE,
        .maxAnisotropy = context.gpu_properties().limits.maxSamplerAnisotropy,
        .compareEnable = VK_FALSE,
        .compareOp = VK_COMPARE_OP_ALWAYS,
        .minLod = 0.0F,
        .maxLod = VK_LOD_CLAMP_NONE,
        .borderColor = VK_BORDER_COLOR_INT_OPAQUE_BLACK,
        .unnormalizedCoordinates = VK_FALSE,
    };
    VK_CHECK(vkCreateSampler(device_, &info, nullptr, &sampler_));
}

Sampler::~Sampler() { destroy(); }

Sampler::Sampler(Sampler&& other) noexcept
    : device_(std::exchange(other.device_, VK_NULL_HANDLE)),
      sampler_(std::exchange(other.sampler_, VK_NULL_HANDLE)) {}

Sampler& Sampler::operator=(Sampler&& other) noexcept {
    if (this != &other) {
        destroy();
        device_ = std::exchange(other.device_, VK_NULL_HANDLE);
        sampler_ = std::exchange(other.sampler_, VK_NULL_HANDLE);
    }
    return *this;
}

void Sampler::destroy() noexcept {
    if (sampler_ != VK_NULL_HANDLE) {
        vkDestroySampler(device_, sampler_, nullptr);
        sampler_ = VK_NULL_HANDLE;
    }
}

}  // namespace vkc
```

Your `create_sampler`, with five of its fields coming from the description and the rest
kept exactly as this chapter set them — including `maxAnisotropy` read from the device
limit rather than hard-coded, and `maxLod` left unclamped.

A `Sampler` holds no allocation, so its move and destroy are the same shape as `Image`'s
with one handle instead of four.

### And the other stb file

```cpp title="code/common/base/src/stb_impl.cpp"
#define STB_IMAGE_WRITE_IMPLEMENTATION
```

Two lines, and the long comment above them in the source is the whole story: this file
holds the **writing** half of stb, which chapter 1.5's screenshot harness uses, and
deliberately not the reading half. Nothing exports `stbi_write_*`, so that one can be
shared globally; `stbi_load` and its 42 companions cannot, which is why both this file and
`image.cpp` above compile their own private copy with `STB_IMAGE_STATIC`.

## Words introduced in this chapter

| | |
|---|---|
| **texel** | one pixel of a texture, as distinct from a pixel of the screen |
| **tiling** | how a driver orders texels in memory; `OPTIMAL` is swizzled for cache |
| **subresource** | one mip level and array layer — the granularity a layout belongs to |
| **mip chain** | the texture pre-filtered at halving sizes, to stop minification shimmering |
| **blit** | a copy that may rescale and filter, unlike a plain copy |
| **sampler** | the independent object describing filtering, wrapping and anisotropy |
| **anisotropic filtering** | extra samples along the stretched axis of a glancing surface |
| **array layer** | one image stacked inside another; six of them make a cubemap |
| **trilinear filtering** | blending between two mip levels as well as between texels |
| **combined image sampler** | one descriptor carrying both a view and a sampler |

## Exercises

1. Set `magFilter` to `VK_FILTER_NEAREST` and make the left quad much larger. Crisp texel squares.
   Now set `minFilter` to `NEAREST` too and look at the right-hand quad.
2. Set `mipmapMode` to `VK_SAMPLER_MIPMAP_MODE_NEAREST`, then set `minLod` to `3.0`. You are now
   forcing a blurrier level than the hardware would choose — which is what a `mipLodBias` does.
3. Force `mip_levels_` to 1 and delete the `generate_mipmaps` call, keeping the one transition to
   `SHADER_READ_ONLY_OPTIMAL`. The tiled quad starts to shimmer.
4. Change both address modes to `CLAMP_TO_EDGE` and look at the tiled quad. Then `MIRRORED_REPEAT`,
   and note the border lines now meet.
5. Change the image format to `VK_FORMAT_R8G8B8A8_UNORM` in both `create_image` and
   `create_texture_view`. Everything gets brighter and flatter, because the sRGB-to-linear
   conversion is no longer happening.
6. Swap `input.uv.x` and `input.uv.y` where `output.uv` is written. The triangle in the texture
   points a different way — that is what a transposed texture coordinate looks like.
7. Delete the final `transition` after the mip loop. The image still draws, because nine of its ten
   levels are in the right layout, and the validation layers name the tenth precisely.
