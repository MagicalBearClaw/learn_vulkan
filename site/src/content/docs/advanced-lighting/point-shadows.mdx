5.3 gave the sun a camera. The sun is far enough away that its rays are parallel, so one box
held every ray that mattered, and one square image held the box. 5.2's lamps are not like
that. A lamp sits in the room and shines in every direction: up at nothing, down at the
floor, sideways at the crates around it. No single camera sees in every direction, and no
single square image holds what they would see.

This chapter brings the three lamps back, in the same places and the same colours, into the
room 5.3 lit with the sun. Each lamp gets six cameras and a depth image with six layers, one
per camera. Shadows cast by a lamp in all directions are **point shadows**. The keys:

- <kbd>1</kbd> shadows on or off
- <kbd>2</kbd> fill each lamp's cube with six rendering passes, or with one multiview pass
- <kbd>3</kbd> how the cubes are read: one texel, bilinear, or nine bilinear reads
- <kbd>4</kbd> set the lamps moving, each around a small circle

```
[info] 1 shadows, 2 six passes or multiview, 3 filter, 4 move the lamps.
[info] shadows on, one multiview pass per lamp, 3x3 bilinear taps
[info] shadow cubes, one multiview pass per lamp: GPU  0.023 ms
```

The camera now starts higher, looking down at the floor, because that is where the shadows
fall.

## Six cameras around a lamp

Take any direction out of the lamp, as a vector (x, y, z). One of the three components is the
largest in size: that is the vector's **major axis**. With its sign, it says which of six
directions the vector leans furthest towards: +x, −x, +y, −y, +z or −z. Every direction has
one, so the six sets of directions with the same major axis cover every direction there is.
Ties sit on the boundaries between sets, and have zero area.

The set whose major axis is +x is every direction with |y| ≤ x and |z| ≤ x. Seen from the lamp
that is a square pyramid around the +x axis, whose sides lean out at y/x = ±1 and z/x = ±1.
The tangent of 45° is 1, so its half-angle is 45° in both directions. A perspective camera
at the lamp, looking along +x, with a vertical field of view of 90° and a square image, sees
exactly that pyramid. Six such cameras, one along each axis, see every direction once.

Those six images are the six faces of a cube centred on the lamp, which is the shape 4.4 used
for a sky. A depth image with six layers, made cube-compatible and read through a cube view,
is a **cube shadow map**. The shader reads it the way 4.4 read its sky: it passes a direction,
and the sampler picks the face from the direction's major axis and the texel from the other
two components. Each layer of the image is one **cube face**.

```cpp title="code/src/5.advanced_lighting/point_shadows/main.cpp"
// Where lamp i is at time t: its place, or a point on a small circle around it.
[[nodiscard]] glm::vec3 lamp_position(uint32_t i, float t) {
    const float angle = kOrbitRates[i] * t;
    return kLamps[i].position +
           kOrbitRadius * glm::vec3(std::cos(angle), 0.0F, std::sin(angle));
}

// The six cameras a lamp needs: one at the lamp, looking down each axis, each seeing
// exactly a quarter turn across so that together they leave no gap and no overlap.
[[nodiscard]] std::array<glm::mat4, kFaceCount> cube_view_projections(glm::vec3 lamp) {
    // A square, 90-degree frustum. There is no y flip here, unlike every other camera
    // in the series: the specification fixes which way up a cube face is read, and the
    // up vectors in kCubeFaces already lay each face out that way. The article works
    // through what that does to triangle winding.
    const glm::mat4 projection =
        glm::perspective(glm::radians(90.0F), 1.0F, kShadowNear, kShadowFar);

    std::array<glm::mat4, kFaceCount> faces{};
    for (uint32_t face = 0; face < kFaceCount; ++face) {
        const glm::mat4 view =
            glm::lookAt(lamp, lamp + kCubeFaces[face].forward, kCubeFaces[face].up);
        faces[face] = projection * view;
    }
    return faces;
}
```

## Which way up a face is

A camera makes an image, and a cube lookup reads one. For the comparison to mean anything, a
texel the lookup reads has to be the texel the camera drew in that direction. The lookup's
side of the agreement is fixed. The specification's table, in the chapter on texture
operations, gives for each major axis the face's layer and two coordinates, s<sub>c</sub> and
t<sub>c</sub>:

| major axis | layer | s<sub>c</sub> | t<sub>c</sub> |
|---|---|---|---|
| +x | 0 | −z | −y |
| −x | 1 | +z | −y |
| +y | 2 | +x | +z |
| −y | 3 | +x | −z |
| +z | 4 | +x | −y |
| −z | 5 | −x | −y |

and then s = ½·s<sub>c</sub>/|m| + ½ and t = ½·t<sub>c</sub>/|m| + ½, where m is the major
component. s runs across the face from 0 to 1 and t runs down it, so t = 0 is the first row of
texels in memory.

The camera's side is the rasteriser. A clip-space position comes out of the vertex shader, the
divide gives normalised device coordinates, and the viewport puts x<sub>ndc</sub> = −1 at
column 0 and y<sub>ndc</sub> = −1 at row 0. So the camera agrees with the lookup exactly when

```
   x_ndc = s_c / |m|        y_ndc = t_c / |m|
```

for every point it draws. Take +x. `glm::lookAt(eye, eye + forward, up)` builds a view space
whose x axis is `normalize(cross(forward, up))` and whose y axis is `cross(x axis, forward)`.
`glm::perspective` with no y flip then gives x<sub>ndc</sub> = x<sub>view</sub>/d and
y<sub>ndc</sub> = y<sub>view</sub>/d, where d is the distance along the camera's axis. For +x,
d is the vector's x component, so the camera needs x<sub>view</sub> = −z and
y<sub>view</sub> = −y. With `up` = (0, −1, 0):

```
   x axis = cross((1,0,0), (0,−1,0)) = (0, 0, −1)     so x_view = −z
   y axis = cross((0,0,−1), (1,0,0)) = (0, −1, 0)     so y_view = −y
```

That is the table's row. The other five rows work the same way, and `kCubeFaces` holds the
answers:

```cpp title="code/src/5.advanced_lighting/point_shadows/main.cpp"
// The six directions a cube map faces, in the order the specification gives its array
// layers, and for each the "up" vector that lays the face out the way a cube lookup will
// read it. The article derives every one of these from the specification's table.
struct CubeFace {
    glm::vec3 forward;
    glm::vec3 up;
};
constexpr std::array<CubeFace, kFaceCount> kCubeFaces{{
    {{1, 0, 0}, {0, -1, 0}},   // +X
    {{-1, 0, 0}, {0, -1, 0}},  // -X
    {{0, 1, 0}, {0, 0, 1}},    // +Y
    {{0, -1, 0}, {0, 0, -1}},  // -Y
    {{0, 0, 1}, {0, -1, 0}},   // +Z
    {{0, 0, -1}, {0, -1, 0}},  // -Z
}};

// One bit per face: all six views of a multiview pass.
constexpr uint32_t kAllFaces = (1U << kFaceCount) - 1;
```

### The mirror

Every camera in this series has flipped y in its projection, because Vulkan's clip-space y
points down. These six do not, because the table, not a monitor, decides which way up the
image goes. That has a consequence for triangles.

Compare the +x face with an ordinary camera standing at the lamp and looking along +x. The
ordinary camera has `up` = +y, and its right-hand side is cross(forward, up) = +z. Changing
`up` to −y rolls the camera half a turn, which negates both of its image axes. Leaving out the
y flip negates y a second time. What remains is x negated: the face is the ordinary camera's
picture with left and right swapped, a **mirror image**. That is the −z in the table's first
row: a cube face is what you would see looking out from the centre of the cube, reflected.

A mirror reverses the order in which a triangle's corners go round. Every triangle this series
draws goes counter-clockwise when its front faces the camera, and 1.13's pipelines say so with
`VK_FRONT_FACE_COUNTER_CLOCKWISE`. In a cube face the same triangle goes clockwise, so the
shadow pipelines declare `VK_FRONT_FACE_CLOCKWISE`, and back-face culling keeps culling what it
should.

The mistake is quiet. Leave the shadow pipelines on counter-clockwise and the culling keeps the
faces turned away from the lamp and discards the ones facing it. The floor, seen from above,
disappears from the cubes, and each crate's far side casts its shadow instead of its near side.
The frame looks right at first glance: 6,776 pixels change, 5,953 of them brighter. The extra
light is along the line where each crate meets the floor:

## The depth a face stored

5.3's fragment shader found itself in the shadow map by multiplying its position by the sun's
matrix. Here there are six matrices per lamp, and the fragment shader does not know which
face saw it. It can work that out, and it does not need any matrix to do it.

The face that saw the point is the one its major axis picks. Let the offset from the lamp to
the point be (x, y, z) and let m = max(|x|, |y|, |z|). That face's camera looks along the major
axis, so the point's distance along the camera's line of sight is m. In view space the camera
looks down −z, so z<sub>view</sub> = −m. `glm::perspective`, with the project's
`GLM_FORCE_DEPTH_ZERO_TO_ONE`, has as its last two rows

```
   z_clip = −f/(f − n) · z_view  −  f·n/(f − n)
   w_clip = −z_view
```

and with z<sub>view</sub> = −m the depth after the divide is

```
   depth = z_clip / w_clip  =  f/(f − n)  −  f·n / ((f − n) · m)
```

which is 0 at m = n and 1 at m = f. Nothing in it depends on which face, or on the face's x
and y: the depth a face stored for a point depends only on the point's major component.

```slang title="code/src/5.advanced_lighting/point_shadows/scene.slang"
// The depth a cube face stored for a point at `offset` from its lamp. The face is the
// one whose axis is offset's largest component, and that component is the point's
// distance along the face camera's line of sight; the rest is that camera's projection.
float cube_depth(float3 offset) {
    float3 size = abs(offset);
    float along = max(size.x, max(size.y, size.z));
    float n = push.globals.shadow_near;
    float f = push.globals.shadow_far;
    return f / (f - n) - f * n / ((f - n) * along);
}
```

This is the depth the rasteriser computed, written in closed form, so the stored depth and
the shader's should be the same number. They are, on this GPU, to the last bit. That is
measured below, and it turns out to matter.

A perspective depth is not a linear function of distance. With n = 0.1 and f = 40:

| m | 0.55 | 1 | 5 | 25 |
|---|---|---|---|---|
| depth | 0.8202 | 0.9023 | 0.9825 | 0.9985 |
| depth per unit of m | 0.33 | 0.10 | 0.0040 | 0.00016 |

The last row is the derivative, f·n/((f − n)·m²). A 32-bit float between 0.5 and 1 has steps
of 2<sup>−24</sup>, about 6.0 × 10<sup>−8</sup>, so at 5 units one step of stored depth is
about 15 µm of distance and at 25 units about 0.37 mm. `D32_SFLOAT` resolves the room easily.

```cpp title="code/src/5.advanced_lighting/point_shadows/main.cpp"
// Texels along each side of each face.
constexpr uint32_t kShadowMapSize = 1024;
constexpr uint32_t kFaceCount = 6;

// Depth from each lamp is kept between these distances, measured along whichever axis a
// face looks down. The floor's farthest corner is 26 units along an axis from the lamp
// furthest from it, wherever key 4 has moved the lamps.
constexpr float kShadowNear = 0.1F;
constexpr float kShadowFar = 40.0F;

```

The far plane is a distance along a face's axis, not from the lamp, so what it has to reach is
the largest major component of any point on the floor. That is 26 units, from the blue lamp to
the opposite corner with the lamp moved as far as key 4 takes it. 40 is comfortable.

## Filling the cube

### The image and its views

The image is 4.4's cube, with depth in it instead of six files:

```cpp title="code/src/5.advanced_lighting/point_shadows/main.cpp"
    void create_shadow_cubes() {
        // 5.3's format question, asked again: the faces are rendered into and then
        // sampled, and filtered by key 3's bilinear modes.
        constexpr VkFormat kShadowFormat = VK_FORMAT_D32_SFLOAT;
        VkFormatProperties properties{};
        vkGetPhysicalDeviceFormatProperties(context().physical_device(), kShadowFormat,
                                            &properties);
        const VkFormatFeatureFlags features = properties.optimalTilingFeatures;
        constexpr VkFormatFeatureFlags kRequired =
            VK_FORMAT_FEATURE_DEPTH_STENCIL_ATTACHMENT_BIT |
            VK_FORMAT_FEATURE_SAMPLED_IMAGE_BIT;
        if ((features & kRequired) != kRequired) {
            throw std::runtime_error(
                "D32_SFLOAT cannot be both rendered into and sampled on this GPU");
        }
        const bool filterable =
            (features & VK_FORMAT_FEATURE_SAMPLED_IMAGE_FILTER_LINEAR_BIT) != 0;
        if (!filterable) {
            spdlog::warn("D32_SFLOAT cannot be filtered here; bilinear reads fall back "
                         "to one texel");
        }

        for (uint32_t lamp = 0; lamp < kLampCount; ++lamp) {
            ShadowCube& cube = shadow_cubes_[lamp];
            // 4.4's cube, made from depth instead of loaded from six files.
            cube.image = vkc::Image(
                context(),
                vkc::ImageDesc{
                    .format = kShadowFormat,
                    .extent = {kShadowMapSize, kShadowMapSize},
                    .usage = VK_IMAGE_USAGE_DEPTH_STENCIL_ATTACHMENT_BIT |
                             VK_IMAGE_USAGE_SAMPLED_BIT,
                    .mip_levels = 1,
                    .aspect = VK_IMAGE_ASPECT_DEPTH_BIT,
                    .array_layers = kFaceCount,
                    .cube = true,
                });
            const std::string name = std::format("shadow cube {}", lamp);
            context().name(cube.image.handle(), VK_OBJECT_TYPE_IMAGE, name.c_str());

            for (uint32_t face = 0; face < kFaceCount; ++face) {
                cube.face_views[face] = create_face_view(cube.image.handle(), face);
            }
        }

        // 5.3's two comparison samplers, now made by vkcommon, with one difference: no
        // border. A cube has no outside -- every direction lands on some face -- and the
        // specification says a cube image ignores the sampler's address modes. A
        // bilinear read that runs off one face's edge takes its missing texels from the
        // neighbouring face instead.
        const auto shadow_sampler = [&](VkFilter filter) {
            return vkc::Sampler(context(),
                                vkc::SamplerDesc{
                                    .mag_filter = filter,
                                    .min_filter = filter,
                                    .mipmap_mode = VK_SAMPLER_MIPMAP_MODE_NEAREST,
                                    .address_mode = VK_SAMPLER_ADDRESS_MODE_CLAMP_TO_EDGE,
                                    .anisotropy = false,
                                    .compare = true,
                                    .compare_op = VK_COMPARE_OP_LESS_OR_EQUAL,
                                });
        };
        shadow_nearest_sampler_ = shadow_sampler(VK_FILTER_NEAREST);
        shadow_linear_sampler_ =
            shadow_sampler(filterable ? VK_FILTER_LINEAR : VK_FILTER_NEAREST);
    }
```

`vkc::Image` gives the image one view, of type `VK_IMAGE_VIEW_TYPE_CUBE`, covering all six
layers. The camera pass samples through it. A rendering pass can also draw into it: the
specification rules out only three-dimensional views as rendering attachments, and the
validation layers accept a cube view. A pass without a view mask, though, draws into the first
layer of its attachment's view, and the cube view's first layer is always +x. Drawing into face
3 alone takes a view that starts at layer 3. Each face gets one, a
`VK_IMAGE_VIEW_TYPE_2D` view of a single layer, a **layer view**:

```cpp title="code/src/5.advanced_lighting/point_shadows/main.cpp"
    // A second view of one layer of a cube, as an ordinary 2D image. A rendering pass
    // without a view mask draws into the first layer of its attachment's view, so to
    // draw into face 3 alone, a pass needs a view that starts at layer 3.
    [[nodiscard]] VkImageView create_face_view(VkImage image, uint32_t face) {
        const VkImageViewCreateInfo info{
            .sType = VK_STRUCTURE_TYPE_IMAGE_VIEW_CREATE_INFO,
            .pNext = nullptr,
            .flags = 0,
            .image = image,
            .viewType = VK_IMAGE_VIEW_TYPE_2D,
            .format = VK_FORMAT_D32_SFLOAT,
            .components = {},
            .subresourceRange =
                {
                    .aspectMask = VK_IMAGE_ASPECT_DEPTH_BIT,
                    .baseMipLevel = 0,
                    .levelCount = 1,
                    .baseArrayLayer = face,
                    .layerCount = 1,
                },
        };
        VkImageView view = VK_NULL_HANDLE;
        VK_CHECK(vkCreateImageView(context().device(), &info, nullptr, &view));
        return view;
    }
```

```cpp title="code/src/5.advanced_lighting/point_shadows/main.cpp"
// One lamp's shadow cube, and the views it is rendered through.
struct ShadowCube {
    // A cube-compatible depth image of six layers. Its own view is a CUBE view of all
    // six: the camera pass samples through it, and the multiview fill renders into it.
    vkc::Image image;
    // Each layer alone, as a 2D view, for the six-pass fill.
    std::array<VkImageView, kFaceCount> face_views{};

    void destroy(VkDevice device) noexcept {
        for (VkImageView view : face_views) {
            vkDestroyImageView(device, view, nullptr);
        }
        image.destroy();
    }
};
```

Three lamps, six faces each, 1024 × 1024 texels of four bytes: 72 MiB of depth. 5.3's one map
was 4 MiB.

### Six passes

The direct way to fill a cube is six times over. Each face gets a rendering pass of its own,
into its layer view, and each pass draws the whole scene with that face's matrix. The vertex
shader finds the matrix from `face_base`, a new push constant:

```cpp title="code/src/5.advanced_lighting/point_shadows/main.cpp"
// 4.5's push constants with one more field, which fills the four bytes of padding that
// were already at the end: which of Globals::faces the shadow pass draws with.
struct PushConstants {
    VkDeviceAddress globals;   // 0
    VkDeviceAddress draws;     // 8
    VkDeviceAddress vertices;  // 16
    uint32_t draw_index;       // 24
    uint32_t face_base;        // 28
};
static_assert(offsetof(PushConstants, face_base) == 28);
static_assert(sizeof(PushConstants) == 32);

// Where each object's DrawData sits in the array the frame writes. The order is fixed by
// write_draws() below and nothing else may reorder it.
constexpr uint32_t kFloorDraw = 0;
constexpr uint32_t kFirstCrateDraw = kFloorDraw + 1;
constexpr uint32_t kFirstLampDraw =
    kFirstCrateDraw + static_cast<uint32_t>(kCrates.size());
constexpr uint32_t kDrawCount = kFirstLampDraw + kLampCount;
```

```cpp title="code/src/5.advanced_lighting/point_shadows/main.cpp"
private:
    // ---------------------------------------------------------------------------
    // Pass one: depth from each lamp, in six directions
    // ---------------------------------------------------------------------------

    void render_shadow_cube(VkCommandBuffer cmd, uint32_t lamp) {
        const ShadowCube& cube = shadow_cubes_[lamp];

        // 5.3's two barriers, unchanged. image_barrier() covers every array layer, so
        // one call moves all six faces.
        vkc::image_barrier(cmd, cube.image.handle(), VK_IMAGE_LAYOUT_UNDEFINED,
                           VK_IMAGE_LAYOUT_DEPTH_ATTACHMENT_OPTIMAL,
                           VK_PIPELINE_STAGE_2_FRAGMENT_SHADER_BIT,
                           VK_ACCESS_2_SHADER_SAMPLED_READ_BIT,
                           VK_PIPELINE_STAGE_2_EARLY_FRAGMENT_TESTS_BIT |
                               VK_PIPELINE_STAGE_2_LATE_FRAGMENT_TESTS_BIT,
                           VK_ACCESS_2_DEPTH_STENCIL_ATTACHMENT_READ_BIT |
                               VK_ACCESS_2_DEPTH_STENCIL_ATTACHMENT_WRITE_BIT,
                           VK_IMAGE_ASPECT_DEPTH_BIT);

        const uint32_t first_face = lamp * kFaceCount;
        if (fill_ == FillMode::SixPasses) {
            // Six rendering passes, each into one layer through its own 2D view, each
            // drawing the whole scene with its own face's matrix.
            vkCmdBindPipeline(cmd, VK_PIPELINE_BIND_POINT_GRAPHICS, face_pipeline_);
            for (uint32_t face = 0; face < kFaceCount; ++face) {
                begin_shadow_pass(cmd, cube.face_views[face], /*view_mask=*/0);
                draw_geometry(cmd, first_face + face);
                vkCmdEndRendering(cmd);
            }
        } else {
            // One rendering pass into all six layers. The view mask says which layers;
            // every draw is then run once per set bit, and the vertex shader is told
            // which run it is in.
            vkCmdBindPipeline(cmd, VK_PIPELINE_BIND_POINT_GRAPHICS, multiview_pipeline_);
            begin_shadow_pass(cmd, cube.image.view(), kAllFaces);
            draw_geometry(cmd, first_face);
            vkCmdEndRendering(cmd);
        }

        vkc::image_barrier(cmd, cube.image.handle(),
                           VK_IMAGE_LAYOUT_DEPTH_ATTACHMENT_OPTIMAL,
                           VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL,
                           VK_PIPELINE_STAGE_2_LATE_FRAGMENT_TESTS_BIT,
                           VK_ACCESS_2_DEPTH_STENCIL_ATTACHMENT_WRITE_BIT,
                           VK_PIPELINE_STAGE_2_FRAGMENT_SHADER_BIT,
                           VK_ACCESS_2_SHADER_SAMPLED_READ_BIT,
                           VK_IMAGE_ASPECT_DEPTH_BIT);
    }

    // 5.3's depth-only rendering instance, into whichever view it is given. With a view
    // mask, layerCount is ignored: the mask is what says how many layers are drawn.
    static void begin_shadow_pass(VkCommandBuffer cmd, VkImageView view,
                                  uint32_t view_mask) {
        const VkRenderingAttachmentInfo depth_attachment{
            .sType = VK_STRUCTURE_TYPE_RENDERING_ATTACHMENT_INFO,
            .pNext = nullptr,
            .imageView = view,
            .imageLayout = VK_IMAGE_LAYOUT_DEPTH_ATTACHMENT_OPTIMAL,
            .resolveMode = VK_RESOLVE_MODE_NONE,
            .resolveImageView = VK_NULL_HANDLE,
            .resolveImageLayout = VK_IMAGE_LAYOUT_UNDEFINED,
            .loadOp = VK_ATTACHMENT_LOAD_OP_CLEAR,
            .storeOp = VK_ATTACHMENT_STORE_OP_STORE,
            .clearValue = {.depthStencil = {.depth = 1.0F, .stencil = 0}},
        };
        const VkExtent2D extent{kShadowMapSize, kShadowMapSize};
        const VkRenderingInfo rendering{
            .sType = VK_STRUCTURE_TYPE_RENDERING_INFO,
            .pNext = nullptr,
            .flags = 0,
            .renderArea = {.offset = {0, 0}, .extent = extent},
            .layerCount = 1,
            .viewMask = view_mask,
            .colorAttachmentCount = 0,
            .pColorAttachments = nullptr,
            .pDepthAttachment = &depth_attachment,
            .pStencilAttachment = nullptr,
        };
        vkCmdBeginRendering(cmd, &rendering);
        set_viewport(cmd, extent);
    }
```

That is 18 rendering passes a frame. Each draws the floor and six crates, so the scene is
recorded 126 times to make three cubes.

### One multiview pass

**Multiview** is the API's way of saying the same draws into several layers at once.
`VkRenderingInfo::viewMask` is a **view mask**: one bit per layer of the attachments, and the
pass draws every set layer. Each draw recorded in the pass is then carried out once for each
set bit, and the vertex shader is told which time it is: the **view index**. The specification
is plain about what `layerCount` means then. It is "the number of layers rendered to in each
attachment when `viewMask` is 0", which leaves it no meaning otherwise. Setting it to 0 in a
multiview pass gives no message and an identical frame. Setting it to 0 in the six-pass path
gives:

```
vkCmdBeginRendering(): pRenderingInfo viewMask and layerCount are both zero.
The Vulkan spec states: If viewMask is 0, layerCount must not be 0
(https://docs.vulkan.org/spec/latest/chapters/renderpass.html#VUID-VkRenderingInfo-viewMask-06069)
```

So one pass per lamp, with a mask of 0b111111 and the cube view as the attachment, draws all six
faces from one recording of the scene: three passes and 21 draws a frame. The view index
reaches the shader as `SV_ViewID`, which is SPIR-V's `ViewIndex`. The specification says that
outside a multiview pass it is zero, so one vertex shader serves both paths: `face_base` names
the first face, and the view index counts on from it.

The two paths give the same pixels. With each of the three filters, the frame from six passes
and the frame from multiview differ in 0 pixels. What changes is the work. On the RTX 4080 the
shadow cubes take 0.033 ms of GPU time with six passes and 0.023 ms with multiview, averaged
over a second by 4.6's timer. Both numbers are small because the scene is seven boxes. The
difference is the cost of 15 more rendering passes, and the CPU's side of it, 105 more draws
recorded, grows with every object in the scene.

### Barriers

5.3's two barriers move the whole image. `vkc::image_barrier` names

calls the square map did. Synchronization validation, switched on as 5.3 described, reports
nothing for any of the 24 combinations of keys 1 to 4.

## Asking the cube

### The samplers and the array

The comparison sampler is 5.3's, now made by `vkcommon`, with one setting changed. A cube has
no outside: every direction lands on some face. The specification says a cube image ignores
the sampler's address modes. With linear filtering, a read that runs off the edge of a face
takes the missing texels from the neighbouring face, so a bilinear comparison near an edge is
still a comparison of four real texels. That is **seamless filtering**, and in Vulkan it is not
an option to turn on. With nearest filtering there is no read to run off: the address is
clamped to the face's edge. The border colour that kept 5.3's outside lit has nothing to do.

The descriptor set holds the three cubes as an array of three, one binding with
`descriptorCount` 3, and each write fills one element of it through `dstArrayElement`:

### The lookup

```slang title="code/src/5.advanced_lighting/point_shadows/scene.slang"
// How much of lamp `lamp` reaches this point: 1 in full light, 0 in full shadow, and
// fractions along the edges when the filter reads more than one texel.
float lamp_visibility(uint lamp, float3 world_position) {
    Globals globals = *push.globals;
    if ((globals.flags & kShadowsOn) == 0) {
        return 1.0;
    }

    float3 offset = world_position - globals.lamps[lamp].position.xyz;
    float depth = cube_depth(offset);

    // Beyond the far plane the comparison would always fail. The far plane reaches the
    // corners of the floor, so this only matters to a reader who moves a lamp outside.
    if (depth > 1.0) {
        return 1.0;
    }

    if (globals.filter != kFilterPcf3x3) {
        return shadow_maps[lamp].SampleCmpLevelZero(offset, depth);
    }

    // 5.3's nine bilinear reads, one texel apart, now on a cube face. The two directions
    // across the face are the two axes that are not its own, and one texel along them
    // is 2 / size of the face at distance 1 -- so 2 * along / size at this distance.
    float3 size = abs(offset);
    float along = max(size.x, max(size.y, size.z));
    float3 across_a;
    float3 across_b;
    if (along == size.x) {
        across_a = float3(0, 1, 0);
        across_b = float3(0, 0, 1);
    } else if (along == size.y) {
        across_a = float3(1, 0, 0);
        across_b = float3(0, 0, 1);
    } else {
        across_a = float3(1, 0, 0);
        across_b = float3(0, 1, 0);
    }
    float step = 2.0 * along * globals.shadow_texel;

    float sum = 0.0;
    for (int y = -1; y <= 1; ++y) {
        for (int x = -1; x <= 1; ++x) {
            // Every tap is compared against this point's own depth, as in 5.3. A tap
            // that crosses an edge reads the next face, whose depths are measured along
            // another axis -- but near an edge the two distances are nearly equal,
            // which is what being near the edge means.
            float3 tap = offset + (float(x) * across_a + float(y) * across_b) * step;
            sum += shadow_maps[lamp].SampleCmpLevelZero(tap, depth);
        }
    }
    return sum / 9.0;
}
```

The one-read path passes the offset itself as the direction. The sampler normalises nothing and
needs nothing normalised: only the ratios of the components choose the face and the texel.

The nine-read path is 5.3's, moved onto a cube face. Across the face the two directions are the
axes that are not the major one. The face spans −m to m in each of them, at distance m, in
`kShadowMapSize` texels, so one texel there is 2m/size. Each tap is the offset moved by whole
texels across the face.

Every tap compares against the point's own depth. A tap near an edge may cross onto the next
face, whose depths are measured along a different axis, and it is tempting to compute each
tap's depth from its own vector instead. Try it, and it is worse. A tap vector is the
point moved across the face, and it is no longer on the surface. Measured along the next face's
axis, it is further from the lamp than the floor in that direction, so the floor appears to be
behind itself. 152 pixels change, most of them at the edge of the square of floor below the
warm lamp, and none of them gets lighter. Near an edge the two axes' distances are nearly equal, which is what
being near the edge means, so the point's own depth is the better guess.

### An array indexed by a loop

`shade` adds the three lamps up in a loop, and indexes `shadow_maps` with the loop counter:

```slang title="code/src/5.advanced_lighting/point_shadows/scene.slang"
float3 shade(VSOutput input, float3 albedo) {
    Globals globals = *push.globals;

    float3 normal = normalize(input.normal);
    float3 to_eye = normalize(globals.view_position.xyz - input.world_position);

    float3 total = globals.ambient.rgb * albedo;
    // shadow_maps is indexed by the loop counter, which is not a constant. That is legal
    // because the device enables shaderSampledImageArrayDynamicIndexing, for 3.4.
    for (uint i = 0; i < kLampCount; ++i) {
        total += lamp_light(globals.lamps[i], input.world_position, normal, to_eye,
                            albedo) *
                 lamp_visibility(i, input.world_position);
    }
    return total;
}

[shader("fragment")]
float4 fragmentMain(VSOutput input) : SV_Target {
    float3 tint = push.draws[push.draw_index].colour.rgb;
    float3 albedo = base_colour_map.Sample(input.uv).rgb * tint;
    return float4(shade(input, albedo), 1.0);
}

// The lamp itself: its colour, unlit.
[shader("fragment")]
float4 lampFragmentMain(VSOutput input) : SV_Target {
    return float4(push.draws[push.draw_index].colour.rgb, 1.0);
}
```

A loop counter is not a **constant integral expression**, and the specification allows an array
of sampled images to be indexed by anything else only with the
`shaderSampledImageArrayDynamicIndexing` feature enabled. The device enables it, since 3.4.
Nothing would report its absence: with the feature turned off, the validation layers are silent,
`spirv-val` accepts the module and the frame is unchanged. This chapter is where that came to
light, and 3.4, whose texture array has the same need, ran without the feature until then.

Slang's `[ForceUnroll]` on the loop would avoid the question entirely: it copies the body three
times with the literal indices 0, 1 and 2, six sampling instructions in the SPIR-V instead of
two. The frame differs from the looped one by 5 pixels, each by one level, which is the
compiler arranging the arithmetic differently.

## Bias, for a lamp

### Slope-scaled, again

5.3 derived its slope-scaled bias from one fact: for a flat surface, the hardware's slope term
is the change in depth across one texel of the shadow map. Nothing in that argument used the
projection, so it holds for a perspective face as it held for the sun's box. The factors come
out the same. Pixels darker than the final frame by more than two levels:

| slope bias | 0 | 1 | 2 | 4 | 8 |
|---|---|---|---|---|---|
| one texel | 541,262 | 289 | 203 | 0 | 0 |
| bilinear | 716,868 | 501 | 249 | 0 | 0 |
| 3×3 reads | 734,363 | 646,058 | 656 | 0 | 0 |

The few hundred left at 1 and 2 are on faces the lamps light at a grazing angle: the side of
the stacked crates and the top of the post. Going from 4 to 8 changes 1,093 pixels with the
3×3 reads, all on the edges of such faces, and no shadow comes away from its crate.

### Zero slope

Below each lamp there is a square of floor with no acne in it at all, even at bias 0. It is
the part of the floor the −y face sees: from (−m, −m) to (m, m) around the point below the
lamp, where m is the lamp's height. The −y camera looks straight down at it, so every point of
that floor is at the same distance along the camera's axis. Its depth is the same everywhere
on the face. It has **zero slope**: no texel's depth differs from its neighbour's, so there is
no acne, and there is also nothing for a slope-scaled bias to scale. Whatever bias that square
gets from the slope term is zero.

So the floor below a lamp is lit only if the depth the rasteriser stored and the depth the
shader computed compare as equal or the right way round. Both are the same formula, worked by
different hardware. Shifting the shader's depth by single steps of the float, a
**unit in the last place**, finds where they stand:

- With n = 0.1 they are equal. One step towards the lamp keeps the square lit. One step away
  darkens 11,751 pixels. 5.3's exercise 6 asked whether `VK_COMPARE_OP_LESS` instead of
  `LESS_OR_EQUAL` changes anything: here, with no constant bias, it darkens 11,714 pixels.
  The square is lit by the "or equal".
- With n = 0.01 they are not. The stored depth lands one or two steps beyond the shader's, the
  square fails its comparison, and 11,725 pixels go dark.

<figure>
  <img src="/learn_vulkan/img/5.4/head-on.png" alt="Two enlarged crops of the floor below the warm lamp. Left: a dark square patch on the floor, sharply edged. Right: the same floor evenly lit" />
  <figcaption>The floor below the warm lamp, with the near plane at 0.01. Left: no constant bias. Right: constant bias 4.</figcaption>

A tie decided by rounding is not something to ship. The slope term cannot help, but
`depthBiasConstantFactor` can. 5.3 found it useless for acne, because acne needs thousands of
its units. Here it needs very few. 5.3 derived its unit for `D32_SFLOAT`:
2<sup>e − 23</sup>, where e is the exponent of the triangle's largest depth. Below a lamp the
floor's depth in the −y face is 0.82, between 0.5 and 1, so e is −1 and the unit is
2<sup>−24</sup>: one step of the stored value. A **constant depth bias** of 4 moves every
stored depth four steps away:

```cpp title="code/src/5.advanced_lighting/point_shadows/main.cpp"
// 5.3's slope-scaled bias for 3x3 bilinear taps. The article explains why 5.3's argument
// carries over to a perspective projection unchanged.
constexpr float kSlopeBias = 4.0F;
// And, for the first time, a constant one: four steps of the depth format. A surface
// that faces a lamp head-on has no slope for the slope term to scale, and the article
// measures what that leaves to chance.
constexpr float kConstantBias = 4.0F;
```

With it, `LESS` darkens nothing, and the near plane at 0.01 gives a frame that differs from the
shipped one in 13 pixels. At the square's distance four steps are 0.7 µm, so no shadow moves.

## The lamps in their own cubes

The lamp spheres are drawn in the camera pass and not in the shadow pass. Drawn into the cubes,
each sphere would sit around its own lamp's cameras. Two things would still save the room.
Seen from inside, every triangle of a sphere faces away, and back-face culling discards it. And
the near plane at 0.1 is outside the sphere's radius of 0.06, so every triangle is clipped
anyway. Each is enough alone: with either, drawing the spheres changes 4,698 pixels by at most 5
levels, which are the bulbs' small shadows from the other two lamps. With neither, no culling and
a near plane at 0.01, a lamp's sphere fills all six of its faces and 745,192 pixels go dark.

`<numbers>` and `<utility>` come back with 5.2's `make_sphere`, which draws the lamps again:

```cpp title="code/src/5.advanced_lighting/point_shadows/main.cpp"
[[nodiscard]] std::pair<std::vector<Vertex>, std::vector<uint16_t>> make_sphere(
    uint32_t rings, uint32_t segments, float radius) {
    std::vector<Vertex> vertices;
    std::vector<uint16_t> indices;
    vertices.reserve(static_cast<size_t>(rings + 1) * (segments + 1));
    indices.reserve(static_cast<size_t>(rings) * segments * 6);

    for (uint32_t ring = 0; ring <= rings; ++ring) {
        const float v = static_cast<float>(ring) / static_cast<float>(rings);
        const float phi = v * std::numbers::pi_v<float>;
        for (uint32_t segment = 0; segment <= segments; ++segment) {
            const float u = static_cast<float>(segment) / static_cast<float>(segments);
            const float theta = u * 2.0F * std::numbers::pi_v<float>;
            const glm::vec3 normal{std::sin(phi) * std::cos(theta), std::cos(phi),
                                   std::sin(phi) * std::sin(theta)};
            vertices.push_back({normal * radius, normal, {u, v}});
        }
    }

    for (uint32_t ring = 0; ring < rings; ++ring) {
        for (uint32_t segment = 0; segment < segments; ++segment) {
            const auto a = static_cast<uint16_t>(ring * (segments + 1) + segment);
            const auto b = static_cast<uint16_t>(a + segments + 1);
            indices.insert(indices.end(), {a, static_cast<uint16_t>(a + 1), b,
                                           static_cast<uint16_t>(a + 1),
                                           static_cast<uint16_t>(b + 1), b});
        }
    }
    return {std::move(vertices), std::move(indices)};
}
```

```cpp title="code/src/5.advanced_lighting/point_shadows/main.cpp"
    void render_scene(const vkc::FrameInfo& frame) {
        vkc::begin_rendering(frame.cmd, frame.view, depth_.view(), frame.extent,
                             {{0.0F, 0.0F, 0.0F, 1.0F}});
        set_viewport(frame.cmd, frame.extent);

        const VkDescriptorSet shadow_set =
            filter_ == ShadowFilter::OneTexel ? shadow_nearest_set_ : shadow_linear_set_;
        vkCmdBindDescriptorSets(frame.cmd, VK_PIPELINE_BIND_POINT_GRAPHICS,
                                pipeline_layout_, 1, 1, &shadow_set, 0, nullptr);

        vkCmdBindPipeline(frame.cmd, VK_PIPELINE_BIND_POINT_GRAPHICS, opaque_pipeline_);
        draw_geometry(frame.cmd, 0);

        // The lamps themselves, drawn only here. In the shadow pass each would sit
        // around its own lamp's camera, and only two accidents would keep it from hiding
        // the room: seen from inside, every triangle faces away and is culled, and the
        // near plane is further out than the sphere's radius.
        bind_indices(frame.cmd, lamp_);
        vkCmdBindPipeline(frame.cmd, VK_PIPELINE_BIND_POINT_GRAPHICS, lamp_pipeline_);
        for (uint32_t i = 0; i < kLampCount; ++i) {
            push(frame.cmd, lamp_.vertex_address, kFirstLampDraw + i, 0);
            vkCmdDrawIndexed(frame.cmd, lamp_.index_count, 1, 0, 0, 0);
        }

        vkCmdEndRendering(frame.cmd);
    }

    // The floor and every crate, with whatever pipeline is bound. face_base is read only
    // by the shadow pass's vertex shader.
    void draw_geometry(VkCommandBuffer cmd, uint32_t face_base) {
        bind_indices(cmd, floor_);
        bind_texture(cmd, floor_set_);
        push(cmd, floor_.vertex_address, kFloorDraw, face_base);
        vkCmdDrawIndexed(cmd, floor_.index_count, 1, 0, 0, 0);

        bind_indices(cmd, cube_);
        bind_texture(cmd, crate_set_);
        for (uint32_t i = 0; i < kCrates.size(); ++i) {
            push(cmd, cube_.vertex_address, kFirstCrateDraw + i, face_base);
            vkCmdDrawIndexed(cmd, cube_.index_count, 1, 0, 0, 0);
        }
    }

    // ---------------------------------------------------------------------------
    // Filling the arena
    // ---------------------------------------------------------------------------

    void write_globals(FrameArena& arena, VkExtent2D extent) {
        Globals globals{
            .view = camera_.view(),
            .projection = projection(extent),
            .view_position = glm::vec4(camera_.position, 1.0F),
            .ambient = glm::vec4(kAmbient, 1.0F),
            .lamps = {},
            .faces = {},
            .shadow_near = kShadowNear,
            .shadow_far = kShadowFar,
            .shadow_texel = 1.0F / static_cast<float>(kShadowMapSize),
            .flags = shadows_ ? kShadowsOn : 0U,
            .filter = static_cast<uint32_t>(filter_),
        };
        for (uint32_t i = 0; i < kLampCount; ++i) {
            const glm::vec3 position = lamp_position(i, lamp_time_);
            globals.lamps[i] = Lamp{
                .position = glm::vec4(position, 1.0F),
                .colour = glm::vec4(kLamps[i].colour * kLampIntensity, 1.0F),
            };
            const std::array<glm::mat4, kFaceCount> faces =
                cube_view_projections(position);
            std::copy(faces.begin(), faces.end(), globals.faces.begin() + i * kFaceCount);
        }
        globals_address_ = arena.write(&globals, sizeof(globals));
    }

    void write_draws(FrameArena& arena) {
        draws_.clear();

        draws_.push_back(draw_data_of(glm::mat4(1.0F), kWhite));

        for (const Placement& crate : kCrates) {
            draws_.push_back(draw_data_of(crate_model(crate), kWhite));
        }

        for (uint32_t i = 0; i < kLampCount; ++i) {
            const glm::mat4 model =
                glm::translate(glm::mat4(1.0F), lamp_position(i, lamp_time_));
            draws_.push_back(draw_data_of(model, glm::vec4(kLamps[i].colour, 1.0F)));
        }

        draws_address_ = arena.write(draws_.data(), draws_.size() * sizeof(DrawData));
    }

    // 4.7's once-a-second average of what the timer measured.
    void record_gpu_time(double ms) {
        if (ms >= 0.0) {
            gpu_ms_ += ms;
            ++gpu_samples_;
        }
        if (elapsed() - stats_started_ < 1.0F || gpu_samples_ == 0) {
            return;
        }
        spdlog::info("shadow cubes, {}: GPU {:6.3f} ms",
                     kFillNames[static_cast<uint32_t>(fill_)], gpu_ms_ / gpu_samples_);
        gpu_ms_ = 0.0;
        gpu_samples_ = 0;
        stats_started_ = elapsed();
    }

    void log_mode() const {
        spdlog::info("shadows {}, {}, {}{}", shadows_ ? "on" : "off",
                     kFillNames[static_cast<uint32_t>(fill_)],
                     kFilterNames[static_cast<uint32_t>(filter_)],
                     moving_ ? ", lamps moving" : "");
    }

    // ---------------------------------------------------------------------------
    // Frame plumbing
    // ---------------------------------------------------------------------------

    void push(VkCommandBuffer cmd, VkDeviceAddress vertices, uint32_t draw_index,
              uint32_t face_base) {
        const PushConstants constants{
            .globals = globals_address_,
            .draws = draws_address_,
            .vertices = vertices,
            .draw_index = draw_index,
            .face_base = face_base,
        };
        vkCmdPushConstants(cmd, pipeline_layout_,
                           VK_SHADER_STAGE_VERTEX_BIT | VK_SHADER_STAGE_FRAGMENT_BIT, 0,
                           sizeof(constants), &constants);
    }
```

```slang title="code/src/5.advanced_lighting/point_shadows/scene.slang"
VSOutput vertexMain(uint vertex_id : SV_VulkanVertexID) {

    output.world_position = world.xyz;
```

```slang title="code/src/5.advanced_lighting/point_shadows/scene.slang"
// 5.2's lamp_light(), unchanged: one lamp, without the ambient.
float3 lamp_light(Lamp lamp, float3 world_position, float3 normal, float3 to_eye,
                  float3 albedo) {
    float3 offset = lamp.position.xyz - world_position;
    float distance = length(offset);
    float3 to_light = offset / distance;

    float attenuation = 1.0 / (kConstantTerm + kLinearTerm * distance +
                               kQuadraticTerm * distance * distance);

    float facing = dot(normal, to_light);
    if (facing <= 0.0) {
        return float3(0.0);
    }

    float3 halfway = normalize(to_light + to_eye);
    float specular_amount = pow(max(dot(normal, halfway), 0.0), kShininess);

    float3 diffuse = facing * albedo;
    float3 specular = specular_amount * kSpecularStrength;
    return lamp.colour.rgb * (diffuse + specular) * attenuation;
}
```

## What changed since 5.3

- 5.2's three lamps back, the sun gone
- a cube shadow map per lamp: a cube-compatible depth image, its cube view, and a 2D view per
  face
- six cameras per lamp, with the face layout derived from the specification's table, and the
  mirror that makes the shadow pipelines' front face clockwise
- the depth a face stored, recomputed in the shader from the major component
- multiview: the `multiview` feature, `PipelineBuilder::view_mask`, `SV_ViewID`, and six faces
  in one pass
- a descriptor array of three cubes, indexed by a loop counter
- a constant depth bias, for the floor the lamps look straight down on
- the comparison sampler moved into `vkcommon`
- `shaderSampledImageArrayDynamicIndexing` enabled, which 3.4 needed and lacked
- 38 chapters in the build now

## Words introduced in this chapter

| | |
|---|---|
| **point shadow** | a shadow cast by a light at a point in the scene, which can fall in any direction from it |
| **cube shadow map** | six depth images, one per face of a cube around a light, read by direction |
| **cube face** | one of the six layers of a cube image, seen by a camera looking along one axis |
| **major axis** | the axis of a direction vector's largest component, with its sign; it picks the cube face |
| **mirror image** | a picture with one axis reversed, which reverses the winding of every triangle in it |
| **multiview** | drawing the same commands into several layers of the attachments in one rendering pass |
| **view mask** | the bits saying which layers a multiview pass draws, one bit per layer |
| **view index** | which of a multiview pass's views a shader invocation is working on; `SV_ViewID` in Slang |
| **layer view** | an image view that starts at one layer of an image and covers some of its layers |
| **zero slope** | a surface whose depth does not change across the shadow map, because it faces the light's camera head-on |
| **constant depth bias** | a depth offset of a fixed number of the depth format's steps, the same for every triangle |
| **unit in the last place** | one step between neighbouring values of a floating-point number |
| **seamless filtering** | a cube map's filtering reading across a face's edge into the neighbouring face |
| **constant integral expression** | an integer the compiler knows, which is all an array of sampled images may be indexed by without `shaderSampledImageArrayDynamicIndexing` |
